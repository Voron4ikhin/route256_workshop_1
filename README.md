# route256 workshop-1

Учебный проект: интернет-магазин из нескольких сервисов, каждый — со слоистой (гексагональной) архитектурой.

## Сервисы

| Сервис          | Роль                                                                 | Протокол наружу | Протокол внутри (к другим сервисам) |
|-----------------|-----------------------------------------------------------------------|------------------|--------------------------------------|
| `cart`          | Корзина пользователя, оформление заказа                              | HTTP/JSON        | gRPC → `loms`                        |
| `loms`          | Учет заказов и остатков товара (Logistics and Order Management)      | gRPC             | —                                     |
| `notifications` | Заготовка под уведомления                                             | —                | —                                     |

API `loms` и `cart` подробно описан в [docs/README.md](docs/README.md).

## Контракты (gRPC)

`.proto`-файлы лежат в [`proto/`](proto) и общие для `cart` и `loms` — `cart` выступает клиентом, `loms` сервером. Конфиг генерации ([`buf.yaml`](buf.yaml), [`buf.gen.yaml`](buf.gen.yaml)) тоже в корне. Сгенерированный код закоммичен в `loms/pkg/api/...` (см. обоснование ниже), поэтому для обычной сборки `buf`/`protoc` не нужны — они нужны, только если меняешь `.proto`.

Перегенерировать после правки контракта:

```bash
make generate           # из корня — сводная цель
# или из конкретного сервиса, самодостаточно:
cd loms && make generate
cd cart && make generate
```

Цель сама поставит нужные версии `buf`, `protoc-gen-go`, `protoc-gen-go-grpc` в локальный `bin/` сервиса (по аналогии с тем, как `install-lint`/`install-smartimports` уже делают это для линтера).

Почему сгенерированный код в git, а не в `.gitignore`: `cart` импортирует пакет `route256/loms/pkg/api/loms/v1` напрямую как обычный Go-модуль внутри `go.work`, без отдельной публикации. Если бы `pkg/api` был в `.gitignore`, склонированный репозиторий не собрался бы без ручного `buf generate` — а требование задания как раз "чтобы было максимально удобно склонировать репозиторий и поднять у себя локально".

## Локальный запуск

```bash
cp .env.example .env
make run-all
```

`make run-all` соберёт линукс-бинарники всех сервисов и поднимет `docker-compose` (`cart` на `:8082`, `loms` — HTTP на `:8083` и gRPC на `:50051`, см. [docker-compose.yml](docker-compose.yml)).

Для разработки без Docker — `make run` внутри каждого сервиса плюс флаги адресов (см. `internal/config` каждого сервиса), либо `go run ./cmd/app -loms_grpc_addr=localhost:50051` и т.п.
